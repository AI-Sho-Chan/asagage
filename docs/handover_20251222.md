## 2) 現時点の学び（次にデータが増えたらやること）
- 5801.T のような「戻らない（負けが続きやすい）タイプ」は、将来データが溜まった段階で
  - `DEMO_ONLY` に落とす / 予算（BudgetFactor）を下げる / 守り条件を強める
  を検討する。
- 8105.T のような「急な動きで一気に損切りになりやすいタイプ」は

  の調整対象として、DailyReplay で検証する。

## 3) 補足（1分足の限界）
- 1分足では「1分の中で、利確と損切りのどちらが先に触れたか」が分からないことがあります。
- その場合は、安全側（損切り扱い）に寄せています（`SL_SAME_BAR`）。

## 4) 週末バッチのABテスト（計算時間の短縮が“儲け”を落とさないか）
目的: 週末バッチの計算時間を減らしつつ、DailyReplay（18:00の仮想売買）で見た成績が落ちないかを確認する。

### 比較条件
- A（現行）: coarse=5回 / refine=5回
- B（案）: coarse=3回 / refine=5回
- DailyReplayの売買ルールは固定（同時1ポジション、決済後のみ再エントリー、クールダウン5分、同一銘柄1日2回まで、方向チェックは常時ON、BudgetFactor反映）。

### 実施方針（“今の週末バッチ結果を汚さない”）
1. まず現行の週末バッチ（A）が完走するまで待つ。
2. Bの候補生成は **VM上で別名/別フォルダに出力**する（Aの `output/bt30/NIGHTLY_YYYYMMDD` や `output/excel/candidates_nextday.csv` を上書きしない）。
   - 例: `output/bt30/NIGHTLY_20251219_B/` と `output/excel/NIGHTLY_20251219_B/` のように分離。
3. DailyReplayはA/Bそれぞれの候補CSVを明示指定して回す（上書き防止のため `--label A` / `--label B` を使う）。

### 比較のやり方（20営業日）
- 同じ日付集合（直近20営業日）で、A/Bそれぞれ DailyReplay を回して日次損益を並べる。
- 指標（最低限）:
  - 日次損益（円、bp）
  - 取引回数、勝率
  - 最大負け（上位負けトレード）
  - `exit_reason` 内訳（利確/損切り/引け）
