# 引継ぎ 2025-12-23 — 候補Importが「前回と違う」事故の原因と再発防止

## 起きていた問題（ユーザーの見え方）
- ASAGAKE（NewDashboardV2）で「Import Candidates」を押しても、**12/19 週末バッチの候補と一致しない**（別の銘柄が混ざる／足りない）。

## 原因（結論）
- Excel が読み込む元ファイル `output/excel/candidates_nextday.csv` が、あるタイミングで **“空のファイル”に上書き**されていた。
- その結果、Excel 側は「候補ゼロ」扱いになり、期待した候補が入らなかった。

## 何が空で上書きしていたか
- `tools/aggregate_candidates_today.py` が、候補が作れなかった（もしくは条件で全て落ちた）ときに、
  `candidates_nextday.csv` を **空で上書きする仕様**だった。
- これは「その日だけ候補ゼロ」ならまだ良いが、実運用では **直前の良い候補まで消してしまう**ため、事故につながる。

## 暫定復旧（当日対応）
- `output/excel/candidates_for_20251219.csv` を `output/excel/candidates_nextday.csv` にコピーして復旧。
- これにより、Excel の Import は **12/19 候補（27行/19銘柄）**を取り込める状態に戻った。

## 再発防止（実装）
- `tools/aggregate_candidates_today.py` を修正し、候補が 0 件のときは **既存の candidates_nextday.csv を上書きしない**（前回の候補を保持）ように変更。
- 代わりに診断ログ（JSON）を `logs/aggregate_candidates_*.json` に出す。
- さらに、書き込みは **一時ファイル→置換**の方式にして、途中で壊れたファイルになりにくくした。
- `scripts/run_nightly_candidates.ps1` も修正し、aggregate の出力（JSON）をログに残すようにした（原因追跡が容易になる）。

## 運用メモ（確認ポイント）
- Excel が読むのは常に `output/excel/candidates_nextday.csv`。
- 「Import の結果が変」なときは、まず `output/excel/candidates_nextday.csv` が空になっていないか（サイズ）を確認する。
- その際、診断ログ `logs/aggregate_candidates_*.json` に「なぜ候補が作れなかったか」が残る。
