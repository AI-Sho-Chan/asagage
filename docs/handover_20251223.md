# 引継ぎ 2025-12-23（候補Import不一致/DEMO場中ログ検証）

## 1. 起きていた問題（Importが「反映されない」ように見える）
- `output/excel/candidates_nextday.csv` が「候補0件」の日に **空のCSVで上書き**され、Excel側で Import すると行が消える/変な状態になることがあった。
- 結果として「週末バッチ/ナイトバッチの結果と合ってない」「候補が空になった」と見える事故が発生。

## 2. 対応（再発防止）
### 2.1 `candidates_nextday.csv` を空で上書きしない
- `tools/aggregate_candidates_today.py` を修正して、候補0件のときは **前回の `candidates_nextday.csv` を保持**するようにした。
- CSV書き込みは「一時ファイル → リネーム置換」で **途中で壊れない**ようにした。
- 診断用に `logs/aggregate_candidates_*.json` を出力（いつ/何行/なぜ0件だったかが追える）。

### 2.2 取り込み元の優先順位（「最新1セット」に寄せる）
- NIGHTLYフォルダが古い/混在している場合に備え、**最新の `candidates_for_YYYYMMDD.csv` を優先**して集計できるようにした。

## 3. 12/23 DEMO（Excel場中ログ）で分かったこと
### 3.1 09:00〜09:05に取引が起きた（本来は「最初の5分は仕掛けない」想定）
- `candidates_nextday.csv` には `NoTradeMin=5` が入っているが、VBA側がその値を見ていなかったため、09:00直後から「先回り注文→成立→利確/損切り」が発生していた。

### 3.2 対応（VBAに `NoTradeMin` を反映）
- `excel/AutoTraderAdvanced.bas` に以下を追加：
  - `NoTradeMin`（ダッシュボードのパラメータ行）を参照し、**09:00から NoTradeMin 分の間は先回り注文を作らない**
  - DEMOの「成立判定」も同様に抑止（最初の数分で成立扱いにならないように）
- この変更は `scripts/update_asagake_vba.ps1` で `ASAGAKE.xlsm` に取り込む運用。

### 3.3 対応（当日中に必ず決済：持ち越しゼロ）
- `RUNNING`（未決済のまま残る）を翌日に持ち越さないため、DEMO側に「時間切れ決済」と「引け前の強制決済」を追加。
- 仕組み（DEMOのみ）：
  - 一定時間（デフォルト30分）を超えて決済していなければ強制決済（`DEMO_TIMEOUT`）
  - 引け前（デフォルト 15:25）に残っていれば強制決済（`DEMO_EOD_FLAT`）
  - 引け前の準備時間（デフォルト 15:15）以降は、損していない場合に先に決済（`DEMO_EOD_SOFT`）
- 設定値は `state/strategy_rules.ini` のキーで調整可能：
  - `demo_max_hold_min`（分）
  - `demo_soft_flat_time`（HH:MM）
  - `demo_flat_time`（HH:MM）

## 6. 12/12（金）16:30に週末バッチが走らなかった原因と対策
### 6.1 何が起きていたか
- 週末VM側の `cron` は動いていましたが、当時の `~/run_weekend_only.sh` が **Windows形式（改行や先頭の特殊文字）** になっており、起動直後にエラーで止まっていました。
- その結果、`~/cloud_logs/weekend_20251212_*.log` が作られず、週末バッチ本体も開始できていませんでした。
- 参考：VMの `~/cloud_logs/cron_stdout.log`（更新時刻 2025-12-13）に以下の形のエラーが残っていました（=「そもそも実行ファイルとして読めていない」）。
  - `run_weekend_only.sh: 1: #!/bin/bash : not found`
  - `run_weekend_only.sh: 2: set: Illegal option -o pipefail`

### 6.2 いまの対策（次回から自動実行が外れにくい形）
- **VM側の `cron` は、リポジトリ内の `~/asagage/vm_run_weekend_only.sh` を直接 `bash` で実行**するように統一（Windowsから `scp` したファイルに依存しない）。
- さらに「VM起動が遅れて16:30に間に合わない」事故の保険として、**16:40にもう一度起動を試す**（ただし2重起動しないようロック付き）。
  - 16:30 / 16:40 の2回とも同じコマンドだが、先に走った方がロックを掴むので、重複実行はしない。
- Cloud Scheduler の `start-weekend-vm` は **金曜16:15（JST）** で有効のまま（起動時間に15分の余裕を持たせる設計）。

### 6.3 運用上の確認方法（迷わない手順）
- 「週末バッチが動いてるか」は `logs/nightly_status.txt` ではなく、まず以下を見る：
  - `~/cloud_logs/weekend_YYYYMMDD_HHMMSS.log`（開始・進捗・完了がまとまって出る）
  - `~/asagage/output/bt30/NIGHTLY_YYYYMMDD...`（出力フォルダが作られて増えていく）
