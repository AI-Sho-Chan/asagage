# Handover 2026-01-29（DEMOログ汚染の抑止＋中間集計）

## 1. 事象（ユーザー報告）
- DailyReplay（18:00の仮想売買メール）の結果が不安定/取引なしが多い
- Excel(DEMO) の Orders が「全部キャンセル」「EODっぽいログが大量」など、場中検証に使いにくい
- Import Candidates が「1銘柄しか入らない」事象が断続（※現在は再現していない）

## 2. 現状確認（2026-01-29 JST時点）
### 2.1 DailyReplay（analysis/daily_replay_YYYYMMDD.json の集計）
- 2025-12-08〜（異常日付 `20990101` を除く想定）で 28日ぶんのファイルが存在
- 合計損益はマイナス、勝ち日より負け日が多い（詳細は別途集計スクリプトで継続監視）

### 2.2 daily_trades（analysis/daily_trades_YYYYMMDD.csv の集計）
- `LIVE_STRONG` は合計プラス、`LIVE_BASE` が合計マイナスの主因になりやすい
- 損益が悪化する主因は `exit_reason=SL`（損切り）側が多い傾向

### 2.3 Excel(DEMO) Ordersログ（output/orders/orders_*.csv）
- 最新 `orders_20260128_205815.csv` は行数が非常に多く、`note=DEMO_EOD_FLAT` が支配的
- 直近7日でも `DEMO_EOD_FLAT` が大半を占め、場中の検証ログとしては「汚染」状態
- 典型的な保有時間が数秒（中央値2秒）になりやすく、場中の意思決定ログとして不自然

## 3. 原因（暫定結論）
- Excel(DEMO) の AutoTick が **市場時間外も動き続け**、EOD相当の「強制フラット処理」を大量に生成していた可能性が高い。
- このため Orders が膨張し、場中の約定/決済の検証が困難になっていた。

## 4. 対応（実装）
### 4.1 市場時間外のDEMO処理を抑止
- `excel/AutoTraderAdvanced.bas`
  - `BridgeTickV1`：市場時間外は即 return（市場時間判定 `IsJpxCashSessionNowV2(Now)`）
  - `RefreshTrendsV2`：DEMO時に `demo_stop_time` を超えたら `StopAutoTickV2` + `IDLE` にして止める
  - DEMOの `Preplace/MarkPending/ProcessDemoOrders` は市場時間内のみ実行

### 4.2 設定
- `state/strategy_rules.ini`：`demo_stop_time=15:35` を追加

## 5. 期待される効果
- 市場時間外の `DEMO_EOD_FLAT` 大量発生が止まり、Ordersログが「場中の出来事」に近づく
- DailyReplay（18:00）とExcel(DEMO)ログの乖離原因を切り分けやすくなる

## 6. 残課題
- Import Candidates の「imported=1」が発生する条件の特定（vba_events.log には `imported=1` が複数回記録あり）
- DailyReplayの「取引なし」多発日の要因整理（候補ゼロ/方向不一致/データ欠損などを日次で可視化）
