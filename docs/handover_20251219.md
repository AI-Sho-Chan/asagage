# 2025-12-19 Handover

## 今日の事象（場中 DEMO の確認で見えた違和感）
- `ASAGAKE.xlsm` を `DEMO_RUNNING` にしても、`Orders` に `preplace (PENDING)` は出るが、`preplace_demo (ORDERED)` に変わらず、疑似約定（`RUNNING` → `tp_demo/sl_demo` → `CLOSED`）が進まないケースがあった。
- `preplace_demo` 行が残り続ける設計のため、`RefreshTrendsV2` を繰り返すと `Orders` が増え続けやすかった（処理が重くなる原因になりうる）。
- 「J が J_th を超えていないように見えるのに、約定・決済ログが出る」点は、検証のための根拠ログが不足していた。

## 対応（VBA）
- `excel/AutoTraderAdvanced.bas`
  - `StartDemoV2 / StartLiveV2` で自動更新ループ（`Application.OnTime`）を起動し、手動ボタンクリック無しでも `RefreshTrendsV2` と DEMO 処理が回るようにした（5秒間隔）。
  - `PreplaceOrdersV2` の対象行判定を強化：
    - `EntryBuyPx/EntrySellPx` が「数値 > 0」のときのみ preplace 対象（`#DIV/0!` や空欄を除外）。
    - `OrderQtyPlan <= 0` の行は除外。
  - DEMO 時の `Orders` 肥大化抑制：
    - `preplace_demo` のうち `ORDERED` / `CANCELLED_AUTO` は毎回削除して入れ替え（`RUNNING` は保持）。
  - 検証用ログの強化（今回追加）：
    - `Orders` に `dash_row`（ダッシュボード行番号）と `bestBid_at_fill / bestAsk_at_fill` を記録し、「本当に価格が触れて約定したのか」を後から追えるようにした。
    - Excel の表示が秒単位で丸められても差が見えるよう、`fill_timer/close_timer`（秒以下のカウンタ）も記録。
    - さらに、約定時点で `qty/price` を固定化し、後からダッシュボードの数式が変わっても `Orders` の過去記録がズレないようにした。
