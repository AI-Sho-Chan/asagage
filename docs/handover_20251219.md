# 2025-12-19 Handover

## 今日の事象（場中 DEMO の確認で見えた問題）

- `ASAGAKE.xlsm` を `DEMO_RUNNING` にしても、`Orders` に `preplace (PENDING)` は出るが、`preplace_demo (ORDERED)` に変わらず、疑似約定（RUNNING→tp_demo/sl_demo→CLOSED）が進まないケースがあった。
- さらに、`EntryBuyPx/EntrySellPx` が `#DIV/0!` や `OrderQtyPlan=0` の行でも「式が入っている」だけで preplace に含まれてしまい、無効な preplace を作ることがあった。
- `preplace_demo` 行が残り続ける設計のため、`RefreshTrendsV2` を繰り返すと `Orders` が増え続けやすかった（ディスク/処理負荷の原因になりうる）。

## 対応（VBA: 自動で回す + 無効行を除外 + preplace_demo の肥大化を抑制）

- `excel/AutoTraderAdvanced.bas`
  - `StartDemoV2 / StartLiveV2` で自動ループ（`Application.OnTime`）を開始し、手動でボタンを押さなくても `RefreshTrendsV2` が定期実行されるようにした（デフォルト 5 秒間隔）。
  - `StopDemoV2 / StopLiveV2` でループ停止するようにした。
  - `PreplaceOrdersV2` の対象行判定を強化：
    - `EntryBuyPx/EntrySellPx` は「式がある」だけでは採用しない（値が数値かつ >0 のときのみ採用）。
    - `OrderQtyPlan <= 0` の行は preplace 対象から除外。
  - DEMO 時の `Orders` 肥大化抑制：
    - `preplace_demo` のうち `ORDERED` / `CANCELLED_AUTO` は毎回削除して入れ替える（`RUNNING` は保持）。

## 運用メモ（ユーザー側手順）

- `ASAGAKE.xlsm` に反映するには、Excel を閉じてから次を実行：
  - `powershell -ExecutionPolicy Bypass -File C:\AI\asagake\scripts\update_asagake_vba.ps1`
- 反映後の確認ポイント（最短）：
  - `Demo Start` → 放置しても `Orders` の `preplace` が `preplace_demo (ORDERED)` に変わる
  - 値動き次第で `RUNNING` や `tp_demo/sl_demo` が増える（疑似約定の進行）
