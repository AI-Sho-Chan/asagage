## 今日やったこと（要点）
- `ASAGAKE.xlsm` の `NewDashboardV2` で **候補取り込み（Import Candidates）** が動く状態に復帰。
- DEMO運用で `Orders` が **「先回り注文 → 約定扱い → 決済（利確/損切り）」** まで進むかを、保存スナップショットで確認。
- 「全部キャンセルに見える」原因の1つだった **DEMO判定（RunStatusV2）の参照先**を修正（ActiveWorkbook依存を排除）。
- さらに、DEMOで「損切りばかり即時成立」になり得る問題を特定し、**TP/SL の計算を“注文の向き（BUY/SELL）ごと”に正しく出す**ように修正。

## 重要な学び（なぜ損切りばかりに見えたか）
### 1) DEMO判定がブレると、勝手にキャンセルが走る
- DEMOなのにDEMO扱いされない瞬間があると、既存ロジックで `CANCELLED_AUTO` が大量に付きやすい。
- 対策として、`RunStatusV2` は **常にこのブック（ASAGAKE.xlsm）**の名前定義を見に行くように修正した。

### 2) “両建ての先回り”なのに、TP/SL を片側の式で流用していた
- 現状の `PreplaceOrdersV2` は、1行の候補から **BUY と SELL の先回り注文を両方** `Orders` に書く。
- しかし `TP_price` / `SL_price` は「その時点の方向（EntrySide）」前提の計算だったため、**逆側の先回り注文に不適切なTP/SL**が付くケースがあった。
- 結果として、DEMOでは「条件を満たした扱い」になって **損切りが即時成立**しやすかった。
- 対策として、`Orders` に書く TP/SL を **BUY注文用 / SELL注文用に別計算**するよう修正した。
