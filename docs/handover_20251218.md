# handover_20251218.md

## 目的
- `ASAGAKE.xlsm` の `NewDashboardV2` で `Import Candidates` が安定して動く状態に戻す。
- DEMO 運用で `Orders` シートが「先回り注文 → 約定扱い → 決済（利確/損切り）」まで追えるようにする。

## 発生していた問題
- `Import Candidates` を押すと候補が入らない／既存の候補が消えることがある。
- `logs/vba_events.log` に `Err 1004: アプリケーション定義またはオブジェクト定義のエラー` が残っていた。

## 原因（わかりやすく）
- `output/excel/candidates_nextday.csv` の改行が「LFのみ」になっていることがあり、VBA 側が「1行の巨大な文字列」として読んでしまうケースがあった。
  - その結果、CSVを正しく行として読めず、候補行の復元に失敗する。

## 対応（実施済み）
- `excel/AutoTraderAdvanced.bas`
  - `ImportCandidatesV2` を **LF/CRLF どちらでも読める**実装に変更（ファイルを丸ごと読み→改行で分割する方式）。
  - 取り込み件数が 0 のときは、既存の候補行を消さない（事故防止）。
  - `ImportCandidatesV2 start/done imported=...` を `C:\AI\asagake\logs\vba_events.log` に記録。
  - DEMO 判定（`IsDemoMode`）を **ThisWorkbook 基準**に修正（別ブックを触っても DEMO と認識がズレない）。
    - これがズレると、DEMO中にも関わらず「自動キャンセル」側の処理が走り、`Orders` が全キャンセルになることがあった。
- `tools/aggregate_candidates_today.py`
  - CSV 出力を **CRLF** に統一（VBA 互換性のため）。
  - 候補を作る元データが空/不十分な場合に備え、
    「最新の単一候補ファイル（例: `candidates_YYYYMMDD_M3.csv`）」へ **自動でフォールバック**するようにした。
    - 出力 JSON に `source` と `source_files` を含める（どの候補が元か追跡しやすくする）。

## 影響範囲
- `Import Candidates` の安定性が上がる。
- `candidates_nextday.csv` の行数が急増した場合でも、`source` を見れば「どの候補を元にしたか」を特定できる。

## 補足: 候補が急に増えるケース
- `candidates_nextday.csv` が 400行以上になる場合、主に以下が原因になりやすい。
  - 1銘柄につき複数プランを採用する運用（意図通りだが行数は増える）。
  - 「候補の元データ」が複数日のファイルを混ぜてしまう（意図しない増え方）。
- 今回は `tools/aggregate_candidates_today.py` 側で `source/source_files` を出すので、
  どの候補ファイルが元になっているか確認してから運用判断できる。

## 運用メモ
- `Import Candidates` の成否確認は `C:\AI\asagake\logs\vba_events.log` を見るのが最短。
- ローカルのナイトバッチは最近失敗が続いている可能性がある（例: Python 依存不足など）。
  - `logs/run_nightly_candidates.log` と `logs/nightly_py_error_*.log` を確認して復旧する。

1) Excel を閉じる

4) `C:\AI\asagake\logs\vba_events.log` に `ImportCandidatesV2 done imported=...` が出ているか確認する
