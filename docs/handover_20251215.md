# 引継ぎ 2025-12-15

## 1) 12/12(金) 16:30（日本時間）に週末バッチが走らなかった原因

結論：**VM側の自動実行（cron）が、スクリプトを「最初の1行目で失敗」して止まっていました。**

よくある原因で、今回のログでは次のようなエラーが出ていました：
- `#!/bin/bash\\r: not found`
- `set: Illegal option -o pipefail`

これは **Windowsで作った`.sh`が「改行コード（CRLF）」になってしまい、Linuxが正しく読めなかった**ときの典型例です。

## 2) 対策（次の金曜に確実に動かす）

- **`.sh`は必ずLinux用の改行（LF）に固定する**  
  - リポジトリ側で `.gitattributes` に `*.sh text eol=lf` を追加済み。
- **VM上で実行するスクリプトは「Gitで取ったもの」を正とする**  
  - `~/asagage/vm_run_weekend_only.sh` を唯一の実行元にする。
  - Windowsから `scp` で `.sh` を上書きすると、またCRLFが混ざることがあるので避ける。

## 3) 週末バッチの完了確認（これを見る）

`logs/nightly_status.txt` は「平日ナイトバッチ用」のログで、週末バッチの確認には向きません。

週末バッチが終わったかは、VMで次を確認するのが確実です：
- `ls -t ~/cloud_logs/weekend_*.log | head`
- `tail -n 80 ~/cloud_logs/weekend_YYYYMMDD_HHMMSS.log`
- `ls -t ~/asagage/output/bt30 | head`
- `ls -la ~/asagage/output/excel/candidates_nextday.csv`
