## 2025-11-22 GCP 週末バッチ時刻ずれの原因と対策

### 背景

- 金曜の週末バッチは GCP VM `asagake-weekend-vm` 上で `run_weekend_only.sh` を cron から起動し、  
  その結果を `gs://asagage-weekend-output/output` → Windows (`Asagage Cloud Sync`) → ASAGAKE ダッシュボード、という流れで利用する想定。  
- しかし 2025-11-21（金）分については、VM 側にも Windows 側にも新しい `NIGHTLY_20251121` や `cloud_logs_weekend_20251121.log` が見当たらず、  
  「週末バッチ自体が動いていないのでは？」という疑いがあった。

### 原因: VM タイムゾーン（UTC）と cron 時刻のズレ

- VM の時刻設定を確認:
  - `date` / `timedatectl` の結果、VM は `Etc/UTC`（UTC）のまま稼働していることを確認。
- ユーザー `shouichi_ikeda` の cron 設定:
  - `gcloud compute ssh shouichi_ikeda@asagake-weekend-vm --zone asia-northeast1-a --command "crontab -l"` で確認したところ、
    ```cron
    30 16 * * FRI /home/shouichi_ikeda/run_weekend_only.sh >> /home/shouichi_ikeda/cloud_logs/cron_stdout.log 2>&1
    ```
    と設定されていた（＝毎週金曜 **16:30 UTC** に実行しようとしていた）。
- いっぽう、Cloud Scheduler の起動・停止ジョブは Asia/Tokyo（日本時間）で設定されている:
  - `start-weekend-vm`: `15 16 * * FRI (Asia/Tokyo)` → 07:15 UTC に VM 起動
  - `stop-weekend-vm`:  `00 22 * * FRI (Asia/Tokyo)` → 13:00 UTC に VM 停止
- その結果:
  - VM が稼働しているのは **07:15〜13:00 UTC** のあいだだけ。
  - 週末バッチの cron は **16:30 UTC** を待っているが、その時刻には VM がすでに停止している。
  - よって、11/21 分の週末バッチは **一度も起動していない**、というのが原因だった。

### 対策: cron の時刻を「07:30 UTC（=16:30 JST）」に修正

- VM に `shouichi_ikeda` としてログイン（`gcloud compute ssh ...`）し、cron を次のように修正した。
  - 変更前:
    ```cron
    30 16 * * FRI /home/shouichi_ikeda/run_weekend_only.sh >> /home/shouichi_ikeda/cloud_logs/cron_stdout.log 2>&1
    ```
  - 変更後:
    ```cron
    30 7 * * FRI /home/shouichi_ikeda/run_weekend_only.sh >> /home/shouichi_ikeda/cloud_logs/cron_stdout.log 2>&1
    ```
    （**07:30 UTC = 日本時間 16:30** なので、Cloud Scheduler による 07:15〜13:00 UTC の稼働時間内に収まる）
- 実際の操作コマンド:
  ```bash
  crontab -l | sed 's/^30 16 \* \* FRI/30 7 * * FRI/' | crontab -
  ```
- その後、再度 `crontab -l` を実行し、`30 7 * * FRI ...` に更新されていることを確認済み。

### 今後の挙動（想定）

- 毎週金曜:
  - 16:15（JST）: Cloud Scheduler `start-weekend-vm` が VM を起動。
  - 16:30（JST）: VM 内 cron が `run_weekend_only.sh` を起動。
  - `run_weekend_only.sh` 内で:
    - `~/asagage` に移動し、
    - 週末バッチ（`nightly_build_candidates.py --run-type weekend`）＋金曜ナイト（`--run-type weekday`）＋ `run_trade_analysis.py` を実行。
    - 最後に `gsutil -m rsync -r "$HOME/asagage/output" "gs://asagage-weekend-output/output"` で GCS に出力を同期。
  - 23 時台（JST）: Windows の `Asagage Cloud Sync` タスクが GCS → `C:\AI\asagage\output` へ rsync を行い、
    - `output/cloud_logs_weekend_YYYYMMDD.log`
    - `output/bt30/NIGHTLY_YYYYMMDD/...`
    などが更新される。
- ユーザー視点では、月曜朝に ASAGAKE ダッシュボードで「候補銘柄取込」ボタンを押すだけで、
  VM 週末バッチで新たに生成された候補銘柄が読み込まれる想定。

### 備考（2025-11-21 分の扱い）

- 11/21（金）については、上記の理由でそもそも週末バッチが起動していない。
- もし「11/21 当日分の週末バッチ結果」を後追いで再現したい場合は、
  - VM 上で `run_weekend_only.sh` を **手動で 1 回だけ実行**し、
  - 実行完了後に Windows の `Asagage Cloud Sync` を手動で走らせる（または自動タスクを待つ）
  ことで、同様のパイプラインを通すことができる。

## 2025-11-22 ASAGAKE V2 VBAモジュール改修とデプロイ

### 概要
ASAGAKE V2 システムの機能要件（ハートビート監視、注文訂正閾値、Live/Demoモード制御など）を満たすため、VBAモジュール `AutoTraderAdvanced` の改修とデプロイ準備を行いました。

### 主な変更点
1.  **ハートビート監視機能の追加**:
    *   `NewDashboardV2` シートのセル `Z2` を監視用セルとして定義。
    *   RSSからのデータ更新（N225現在値）を検知し、`Z2` に最終更新時刻を表示する `CheckRssHeartbeat` 関数を実装。
2.  **注文訂正閾値パラメータの追加**:
    *   ダッシュボードの 24列目（X列）に「注文訂正閾値(tick)」パラメータを追加。
    *   `ModifyOrderRSS` 関数内でこの値を参照し、現在価格との乖離が閾値未満の場合は訂正注文をスキップするロジックを実装。
3.  **Live/Demo モード制御の強化**:
    *   `PlaceOrderRSS` および `ModifyOrderRSS` 関数において、システムステータス（`A3`セル）が "LIVE_RUNNING" の場合のみ実際にRSS注文を発行するように変更。それ以外の場合はログ出力のみ行う（Demoモード）。
4.  **Pre-order 実行ロジックの実装**:
    *   `PreplaceOrdersV2` 内で生成された "PENDING" 状態の注文を、実際に発注処理へ回す `ExecutePreplaceOrders` を実装。
5.  **不具合修正**:
    *   `EnsureParamFormulas` における「行継続文字数が多すぎる」コンパイルエラーを、配列初期化を分割することで解消。
    *   日本語文字化け対策として、モジュールファイルを `cp932` エンコーディングで保存・処理するように統一。
    *   `LogPreOrder` 関数の破損および重複定義の問題を修正。
