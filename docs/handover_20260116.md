# Handover 2026-01-16

## 背景 / 症状
- `ASAGAKE.xlsm` の `Import Candidates` を押すと、候補が **1銘柄（例: 6525.T）しか表示されない**。
- 週末バッチ側では「候補は揃っている（前週と変わらない）」認識があるのに、Excel の表示が一致しない。

## 原因（結論）
- Excel/VBA の Import が壊れているのではなく、Excel が読む入力ファイル `output/excel/candidates_nextday.csv` が **1行しかない**ことが直接原因。
- 一方で、Bタイプの週末バッチで出力された候補（例: `output/excel/candidates_nextday_B_coarse3.csv`）は **27行/19銘柄**など十分に存在する。
- しかし nightly（16:30）後処理が `tools/aggregate_candidates_today.py` により `candidates_nextday.csv` を再生成し、厳しめのフィルタで **1行まで削れてしまい**、翌営業日の Import が 1銘柄になる。

## 対応（壊さずに足す / 恒久対策）
- `tools/aggregate_candidates_today.py` に「出力が少なすぎるときは B候補へ自動フォールバック」する挙動を追加。
  - 既存の `candidates_nextday.csv` を読む運用（VBA側）を変更せず、**CSV生成側だけで整合**させる。
  - 新規引数: `--fallback-min-rows`（デフォルト 3）
  - 集計結果の行数が `fallback-min-rows` 未満なら、`output/excel/candidates_nextday_B_coarse3.csv`（またはBスナップショット）を優先して `candidates_nextday.csv` を作る。

## 運用手順（いま直す / 手動ワークアラウンド）
- いま手元で `candidates_nextday.csv` が 1行になっている場合は、次を1回実行すると復旧する：
  - `python tools/aggregate_candidates_today.py --output output/excel/candidates_nextday.csv`
  - これで B候補が存在すれば `candidates_nextday.csv` が複数行に戻る。

## 再発防止
- nightly が `candidates_nextday.csv` を更新する運用は維持しつつ、上記フォールバックにより「1銘柄だけ」へ縮退しにくくした。
- 診断が必要なら `--diag-json` で出力元（NIGHTLY or B候補）とフィルタ条件を追跡できる。

## 変更ファイル
- `tools/aggregate_candidates_today.py`
  - `--fallback-min-rows` 追加
  - `candidates_nextday_B_*.csv` をフォールバック元として扱うロジック追加
