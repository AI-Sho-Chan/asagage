# Handover 2026-01-16

## 事象
- 平日 08:50 のタスクが「起動した」通知は出るのに、PC画面上に Excel が出てこない。
- その後に手動で `ASAGAKE.xlsm` を開こうとすると「他のユーザーが使用中」の扱いになり **読み取り専用** でしか開けない。
- 「Import Candidates」で候補銘柄が **1つだけ** になることがある（以前は複数）。

## 原因（結論）
### 1) Excelが“見えない場所”で起動してロックしている
- タスク `ASAGAKEデモ自動実行` の XML を見ると `<LogonType>Password</LogonType>` になっていた。
- これは「ユーザーがログオンしていなくても動く」方式のため、Excel が **画面に出ないセッション（Session 0）** で起動することがあり、
  その Excel が `ASAGAKE.xlsm` を掴んだままになって **ロック** する。
- その結果、本人が開くと読み取り専用になる。

### 2) 「候補が1つだけ」は、CSVがその瞬間“1行しか無い/壊れている”ケース
- `ImportCandidatesV2` は基本的に `output/excel/candidates_nextday.csv` の内容をそのまま取り込む。
- 取り込み時点で候補CSVが **1件**（または途中書き/空）だと、結果として **1件** になる。
- これは「VBAのフィルタ」よりも、「候補CSVがその瞬間に小さくなっていた」可能性が高い。

## 対応（実施したこと）
### 1) “正しい方式”の朝タスクを新規作成
- 新しいタスク `Asagake-MorningDemo` を作成（`LogonType=InteractiveToken`）。
  - ログオン中の画面でのみ実行されるため、Excelが“見えない場所”で起動しにくい。
  - 実行内容：`wscript.exe C:\AI\asagake\Step1_Morning.vbs`
- 旧タスク `ASAGAKEデモ自動実行` は **権限不足で無効化できなかった**。
  - 管理者権限でタスクスケジューラから無効化/削除が必要（下に手順）。

### 2) 朝スクリプト（`Step1_Morning.vbs`）を安全化
- `logs/morning_task.lock` により多重起動を防止。
- `logs/morning_task_latest.log` に実行ログを出す。
- `ASAGAKE.xlsm` を開いた時点で **ReadOnlyなら即終了**（読み取り専用コピーを閉じる）。
  - “ロック中にさらに壊す”のを防ぐ。

### 3) ImportCandidatesV2 を保護（候補CSVが小さすぎるときにダッシュボードを壊さない）
- `excel/AutoTraderAdvanced.bas` の `ImportCandidatesV2` にガードを追加：
  - 候補CSVの **実データ行数が 5 未満** の場合は import をスキップして終了。
  - 目的：候補CSVが一時的に 0〜1件になった瞬間に、ダッシュボードを 0〜1件に **上書きしてしまう事故** を防ぐ。

## ユーザー側で必要な作業（重要：ロック解消と再発防止）
### 1) いま発生しているロックを解消する（どちらか）
- 方法A：PCを再起動（いちばん確実）
- 方法B：管理者で Task Manager を開いて、見えない Excel（Session 0）を終了
  - 例：`EXCEL.EXE` が SessionId=0 のプロセスが残っているとロック継続。

### 2) 旧タスク `ASAGAKEデモ自動実行` を無効化/削除（管理者が必要）
- タスクスケジューラを **管理者として実行** → `ASAGAKEデモ自動実行` を「無効」または「削除」。
- 旧タスクが残っている限り、また Session 0 Excel が起動してロック再発する恐れがある。

## 確認方法
- ロックの有無確認：
  - `Get-Process EXCEL | Select Id,SessionId,MainWindowTitle`
  - SessionId=0 の Excel が残っていないことを確認。
- 朝タスクのログ：
  - `C:\AI\asagake\logs\morning_task_latest.log`
- 候補CSVの件数確認：
  - `C:\AI\asagake\output\excel\candidates_nextday.csv`（行数=ヘッダ+件数）
