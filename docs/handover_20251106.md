# Handover Notes (2025-11-06)

## 1. 週末バッチ（週次スクリーニング）
- `scripts/check_trading_day.py` を追加。  
  - 祝日ライブラリ（jpholiday）に加えて、`data/raw/yahoo_1m/<ticker>/<date>.parquet` が存在するかを確認し、実際に分足データが取引日分そろっている場合のみ「trading-day」と判断します。  
  - 参照銘柄は `1301.T / 1332.T / 7203.T / 9984.T`。必要に応じて増やすか、別銘柄に変更しても構いません。
- `scripts/run_weekly_screening.ps1` を全面改修。  
  - 実行日（デフォルトは金曜）から **最新の取引日まで自動的にさかのぼり**、その日付を `resolvedTag` として coarse / refine / 集計を行います。金曜が休場でも木曜・水曜…と順に探すため、週末バッチが欠落しません。  
  - 集計フェーズでは `tools/aggregate_weekly_candidates.py` を呼び出し、`code` 列しかない CSV や `forward_exp_boot_mean` のみ出力されるケースでも統合できるよう修正済みです。  
  - 完了時に `output/excel/weekly_candidates_<resolvedTag>.csv`、`weekly_candidates_latest.csv`、`candidates_nextday.csv` が同一内容で更新されます。

## 2. ナイトバッチ（平日夜間）
- `scripts/run_nightly_candidates.ps1` に休日判定を追加。  
  - 金曜・祝日・年末年始はログに `skip` を出して即終了します（exit 0）。  
  - 月～木は従来どおり `nightly_build_candidates.py` を実行。  
  - スケジューラ側のトリガーは外さなくても安全ですが、不要なジョブを削除するとログがすっきりします。

## 3. ASAGAKE.xlsm と SUITE 連携
- `excel/AutoTraderAdvanced.bas` を更新。  
  - `ImportCandidatesV2` の完了直後に `ApplyDynamicSignalsV2` → `PreplaceOrdersV2` を自動実行し、すべてのセッション（AM0930～AM1030）・すべてのシグナルモード（j-only / j-cross）の候補について **BUY/SELL 指値と TP/SL** を Orders シートへ書き出します。  
  - Orders シートでは `note` 欄に `session=AM0930;mode=j-cross` のようなメタ情報を付与しています。SUITE はこの文字列を読み取って、「どの時間帯・どのロジック由来の指値か」を判別し、約定後の後続処理を切り替えられます（例: 朝寄りの建玉は速やかにロット調整する等）。  
  - 「デモ取引」「本番取引」ボタンでステータスセル `A3:B3` が再結合されるよう修正し、結合されていない状態でもエラーになりません。

## 4. 運用フロー（まとめ）
1. **週末（金曜 16:30）**  
   - `run_weekly_screening.ps1` を実行。祝日でも直近取引日で走るため、週末バッチが欠落しません。  
   - 完了すると `candidates_nextday.csv` に翌営業日（通常は月曜）向けの候補が反映されます。
2. **平日ナイト（月～木）**  
   - `run_nightly_candidates.ps1` が通常運転。金曜と祝日は自動スキップします。  
3. **Excel での手順**  
   - 「候補銘柄取込」ボタンを押すと、Orders シートに先回り指値（BUY/SELL と TP/SL）が生成されます。  
   - SUITE 側は `note` 情報で session / mode を判別し、指値の扱いやロット調整を柔軟に切り替えてください（例: AM0930 の j-cross は寄り直後に成り行きに切り替える、など）。

## 5. 今後の検討・推奨事項
- walk-forward テスト  
  - 現在は「固定の train → forward」構成。複数ウィンドウで forward 検証を転がす方式（rolling walk-forward）へ移行すると、パラメータの頑健性評価がより信頼性の高いものになります。  
  - 実装には過去分足データを利用予定。既にローカルに保存されている `data/raw/yahoo_1m` フォルダを再利用します。
- 朝寄りセッションの追加検証  
  - `output/bt30/WEEKLY_<date>/RUN_refine_*` 配下の `_SUMMARY_FORWARD.csv` や `hypothesis_trade_ledger.csv` を利用し、ヒット率・ボラティリティ・板厚を定期的に分析してください。  
  - 成績が良いセッションは、Orders シートに既に反映されているため、SUITE 側での取り込み設定を追加するだけで実運用に組み込めます。
- 休日検知のカスタマイズ  
  - 新規の臨時休場が公表された場合でも、分足データがダウンロードできなければ自動的に休場扱いになります。必要であれば `check_trading_day.py` の参照銘柄を増やすなどで補強してください。---
