# Handover 2026-01-12

## 目的
- 平日18:00の `DailyReplay`（仮想売買）メールが「届かない」問題を復旧し、PCがスリープ中でも動くようにする。

## 何が起きていたか（原因）
- Gmail認証が失効しており、送信が `BadCredentials`（ユーザー名/パスワード不一致）で失敗していた。
- タスクスケジューラが `Interactive only`（ログイン中のみ）で動く設定だったため、PCがスリープ/未ログインだと実行されない可能性が高かった。

## 対応（実施済み）
### 1) SMTP（メール送信）を復旧
- Gmailのアプリパスワードを再発行し、`C:\AI\asagake\state\smtp.json` の `pass` を更新。
- `tools\simulate_daily_replay.py --email` のテスト送信で、受信を確認。

### 2) タスクスケジューラをSYSTEM実行へ変更（スリープ対策）
- `Asagake-DailyReplay` を `Run As User: SYSTEM` で作り直し（平日18:00）。
- タスク設定で「スリープを解除してこのタスクを実行する」を有効化。
  - ノートPC運用の場合は「バッテリー駆動中は開始しない/停止する」がONだと止まるので、運用に合わせてOFF検討。

## 追加の安定化（コード）
- `scripts/run_daily_replay.ps1` を改善：
  - 実行対象 `tools\simulate_daily_replay.py` の存在確認（無ければログに残して即失敗）
  - `exit_code` と `=== end ===` を必ずログへ追記
  - 例外は `.ToString()` で詳細までログに残す
- commit: `607a9b0b4a`（Harden DailyReplay task logging and script path）
- さらに `scripts/run_daily_replay.ps1` を改善：
  - リポジトリ内の `.venv` が存在する場合は `.venv\Scripts\python.exe` を優先して使用（SYSTEM実行でも依存関係が揃う）
  - 1日に複数回起動されても「1日1通」になるよう送信済みフラグを追加（`logs\daily_replay_sent_YYYYMMDD.flag`）
    - 送信後に同日再実行すると `already sent today; skip run` でスキップ
- commits: `f50bc34ad6`（Use repo venv Python for DailyReplay task by default）, `b261e9dc73`（Avoid duplicate DailyReplay emails and retry on send failure）

## 確認方法（再発時の切り分け）
- ログ一覧：`C:\AI\asagake\logs\daily_replay_task_*.log`
- 最新ログ確認：`Get-Content C:\AI\asagake\logs\daily_replay_task_YYYYMMDD.log -Tail 200`
  - `Mail sent to ...` が出ていれば送信成功
  - `BadCredentials` が出ていれば `state/smtp.json` が原因
  - `replay script not found` が出ていればリポジトリ/パスが原因
  - `already sent today; skip run` が出ていれば「多重実行は防げている」（正常）
