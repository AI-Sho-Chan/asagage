# Handover 2026-01-12

この引継書は、週末VM（週末バッチ）とローカルPC（DailyReplay 18:00）の運用が一時的に崩れた原因と、復旧方針をまとめたものです。

## 1) 何が起きていたか（症状）
- **DailyReplay（平日18:00の仮想売買メール）が、2025-12-26以降届かない日が出た。**
- **ローカルの `output/excel/candidates_for_20260109.csv` が 1行に見え、「週末バッチが失敗した？」と誤認しやすい状態になっていた。**

## 2) DailyReplay が止まった原因と対策
### 原因（根本）
- ローカルPCのGitが **sparse-checkout** 状態になっており、`tools/` 配下が欠けていた。
  - その結果、タスクから `tools/simulate_daily_replay.py` が見つからず失敗していた。
- さらに、`scripts/run_daily_replay.ps1` が渡している引数が、Python側の仕様と一致していない時期があった。

### 対策（コード・運用）
- sparse-checkout を解除して `tools/` を復元。
- `scripts/run_daily_replay.ps1` を修正し、Python側へ `--date` を渡す形に統一。
- ログ文字化けを防ぐため、PowerShell出力を `Out-File -Encoding utf8` に統一。
- `tools/simulate_daily_replay.py` 側に `--email/--recipient/--smtp` を追加し、同一コマンドでメール送信できるようにした。

### 重要（残るブロッカー）
- `state/smtp.json` の Gmail 認証で **BadCredentials** が出る場合、メール送信は失敗する。
  - この場合はコードでは直らないため、Gmailの **アプリパスワード更新** → `state/smtp.json` の `pass` 更新が必要。

## 3) 週末バッチ（2026-01-09）の見え方がズレた件
### 事実（VM側の生成物）
- VM側では B出力（粗探索=3回）として、次が生成されている：
  - `gs://asagage-weekend-output/output/excel/candidates_nextday_B_coarse3.csv`（27行/19銘柄）

### ずれた理由
- ローカルの `output/excel/candidates_for_20260109.csv` は「当日スナップショット」だが、集計条件や出力元の違いにより 1行に見えることがある。
- 週末VMの“本命出力”は、GCS側の `candidates_nextday_B_coarse3.csv` を基準に確認するのが確実。

## 4) 次にやること（優先順）
1. **メール送信の完全復旧**：`state/smtp.json` の認証（アプリパスワード）を更新。
2. **DailyReplayタスクの安定化**：PCログイン無しでも動く実行方式（SYSTEM実行など）に変更するか検討。
3. **週末バッチ確認のルール統一**：週末バッチの成果確認は、まずGCSの `candidates_nextday_B_coarse3.csv` を見る。
