# Handover Notes (2025-10-27) — RSS Formula Safeguard

## 事象と原因
- NewDashboard の I6 以降の楽天 RSS 関数（=RssMarket(...), ほか）が空白になった。
- 原因は、`scripts/fix_dashboard_formulas.py` を実行し、openpyxl で `SHINSOKU.xlsm` を直接書き換えたこと。openpyxl は外部アドイン式や保護情報を保持できず、書込み時に式を欠落させ「値なし」状態にしてしまった。

## 復旧
- `SHINSOKU_backup_20251025_172612.xlsm` から `SHINSOKU.xlsm` を復元。
- NewDashboard の I6 以降には元の `=RssMarket(...)` 式（日本語名）を戻し、妥当な保護状態に復旧。
- 2025-10-27 12:00 JST 時点で `scripts/restore_dashboard_formulas.py`（COM 経由・R1C1 指定）により I-V 列へ式を再展開（600 行）。Q列は「最良買気配値」、R列は「最良売気配値」を使用し、銘柄コードからサフィックス（例: `.T`）を除去したうえで数値化して渡すよう補正済み。
- L 列（シグナル点灯）は `Selected=1` かつ `|現在のJ値| >= |J_th|` のときに `BUY/SELL` を即時表示し、必要な価格（最良買/売または代替値）が欠損している場合は `NO_PRICE` を表示する。M 列（シグナル種別）はシグナル点灯列と `SignalMode` を組み合わせて `BUY / j-only` 等を自動表示し、`NO_PRICE` の場合はそのまま警告を出す。

## 対処（恒久策）
- 問題スクリプト削除: `scripts/fix_dashboard_formulas.py` をリポジトリから削除（PC からも削除済み）。
- 外部ライブラリ禁止: openpyxl などで `SHINSOKU.xlsm` を直接編集しない。RSS 式は必ず VBA (`InstallRealtimeFormulas`, `SetColumnFormula` with FormulaLocal) または COM（pywin32）経由で設定する。
- バックアップ運用: 編集前に `SHINSOKU_backup_*.xlsm` を作成。異常時はバックアップから復旧してから作業。
- ドキュメント化: `AGENTS.md`, `NEXT_STEPS.md`, `docs/codex.md` にルールを明記。今回の経緯を本ハンドオーバーに記録。
- ガード導入: `scripts/guard_no_openpyxl_xlsm.py` と `.githooks/pre-commit` を追加（openpyxl×xlsm の不正書込みを検知）。

## 仕様メモ
- Selected 列: “Push Candidates” 後は全行 `1`。実発注時 (“Start Auto”) に当日重複防止のため発注行だけ `0` に落とす。再開は手動で `1` に戻すか、候補 CSV を再ロード。

## 今後の運用
- `SHINSOKU.xlsm` は Excel/VBA/COM のみで扱う。外部ライブラリ（openpyxl 等）での直接編集は禁止。
- 変更時は必ずバックアップ → 変更 → 検証 → 交換（swap）を徹底し、`docs/handover_YYYYMMDD.md` に記録する。

## 2025-10-27/28 Nightly バッチ不具合と対処（1分足 Parquet 列重複）

現象
- `nightly_build_candidates.py` 実行が最初のプランで停止し、`logs/nightly_status.txt` が `state=error` で終了。
- 直接再現したところ、`scripts/bt_opt30_forward.py --use-local-raw` 実行中に以下の例外で落ちることを確認。
  - ValueError: Cannot set a DataFrame with multiple columns to the single column amt

原因
- ローカル保存の 1 分足 Parquet（`data/raw/yahoo_1m/<ticker>/<date>.parquet`）に MultiIndex 列が含まれ、`Adj Close/Close` 等の列が重複。これを素直に `df["close"]` と扱うと DataFrame になり、`amt`（1列）に代入できず例外。

対処（コード強化 + データ修復）
- コード修正: `scripts/bt_opt30_forward.py` の `load_local_1m_chunks` で MultiIndex/重複列を正規化し、OHLCV を一意に抽出（Adj Close を除外）。
- データ修復: `scripts/clean_yahoo_parquet_duplicates.py` を作成し、`data/raw/yahoo_1m` 配下の全 Parquet を走査・列重複を除去して再保存（約 15,702 件を修復）。

検証・再実行
- 修正後、サンプル 5 銘柄で単体実行 → 正常終了・成果物生成を確認。
- ユニバース縮小（50 銘柄）で `nightly_build_candidates.py` を再実行し、`state=success`・10 プラン完走を確認。成果は `output/bt30/NIGHTLY_20251027/*` および `output/excel/candidates_nextday.csv` に出力。

備考
- 今後フルユニバース（300 銘柄）でも同不具合は発生しない見込み。Parquet 追加時は `scripts/clean_yahoo_parquet_duplicates.py --dry-run` による点検を推奨。
