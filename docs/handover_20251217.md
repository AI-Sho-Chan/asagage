# Handover 2025-12-17

## TL;DR
- **重要バグ対応（未反映の可能性あり）**: DEMOで `preplace_demo` は記録されるのに、価格到達後の **約定(FILLED) / 利確・損切り(TP/SL)** が Orders に増えない問題に対し、VBA側に **DEMO約定/決済の擬似実行ロジック**を追加した。
- **重大副作用の抑制**: これまで「指数トレンドの AllowedSide が変わるたびに Orders の反対側を全部 CANCELLED_AUTO にする」挙動があり、TP/SL まで巻き込んでいたので、**preplace系(PENDING/ORDERED)だけを対象**にした。

## 1) DEMOで「約定/利確損切り」が記録されない問題
### 症状
- `NewDashboardV2` で DEMO_RUNNING にして `RefreshTrendsV2` を回すと、Orders に `mode=preplace_demo` / `status=ORDERED` は増える。
- しかし、価格が到達しても `FILLED` が出ず、約定後に出るはずの `TP/SL`（決済注文）も出ない。

### 原因（わかりやすく）
- 現状のVBAは「先回り注文（preplace）を Orders に**書き込む**」ところまでしかやっておらず、DEMOでは「**価格に到達したら約定したことにする**」処理が入っていなかった。
- さらに、指数トレンドの変化で Orders の反対売買が全部 `CANCELLED_AUTO` にされる挙動があり、これが **決済側（SELL/BUY）まで巻き込み**やすかった。

### 対応
- `excel/AutoTraderAdvanced.bas` に以下を追加・変更:
  - `RefreshTrendsV2` の最後で、DEMO時に `ProcessDemoOrdersV2` を呼ぶ。
  - `ProcessDemoOrdersV2`:
    - `preplace_demo ORDERED` が板（BestBid/BestAsk）に到達したら `RUNNING` にして `fill_ts/fill_price` を記録
    - その時点で `tp_demo` と `sl_demo`（OCO）を Orders に追加
    - `tp_demo/sl_demo` が到達したら exit を `FILLED` にし、エントリー行を `CLOSED` にして `pnl_bp` を計算
  - `CancelOppositeOrders`:
    - 以前: Ordersの反対サイドを **無条件で全部 CANCELLED_AUTO**
    - 修正後: `mode` が `preplace` / `preplace_demo` かつ `status` が `PENDING/ORDERED` の行だけをキャンセル
    - 追加: **DEMO_RUNNING の間は CancelOppositeOrders 自体を呼ばない**（DEMOのOrdersログが `CANCELLED_AUTO` だらけになるのを防ぐ）

### ブック側への反映（重要）
この修正は **リポジトリの `.bas` に入っただけ**なので、`ASAGAKE.xlsm` のVBAに反映する必要がある。

- 自動反映（バックアップ付き）: `scripts/update_asagake_vba.ps1`
  - 事前に `ASAGAKE.xlsm` を閉じる
  - 実行例:
    - `powershell -ExecutionPolicy Bypass -File C:\AI\asagake\scripts\update_asagake_vba.ps1`
  - 失敗する場合:
    - Excelの設定「VBAプロジェクト オブジェクトモデルへの信頼アクセス」がOFFだとVBProjectに触れない

## 2) Top200常連の1分足を“永久保存”する（minute_cache育成）
### 目的
- Yahooの1分足は遡れる日数が限られるため、**毎週末にまとめて集める**だけだと「十分な履歴が揃わない」。
- そこで「Top200常連（=よく上位に来る銘柄）」を **毎日保存**して、履歴を積み上げる。

### 実行内容
- `data/universe/top_regulars_ever.csv` を前提に minute_cache を深掘りする処理を回した。
- `scripts/run_update_regulars_1m.ps1` で:
  - 過去60日を取りに行く（可能な範囲で）
  - 足りない分は backfill（最大120日）で埋めに行く（取れる範囲だけ）
  - 保存先の一例: `cache/yahoo_1m_regulars/`
  - その後、GCS `gs://asagage-weekend-output/yahoo_1m_regulars` に同期

### 安定化対応
- `scripts/run_update_regulars_1m.ps1` 内の `gsutil` 呼び出しで `.cmd` を探せず失敗するケースがあったため、`gsutil.cmd` を自動検出して使うように修正。
