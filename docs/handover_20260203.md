# Handover 2026-02-03

## 1) Cursor+Codex の通信中断（ECONNRESET）監視の強化

### 背景 / 目的

Cursor+Codex の利用中に「タスクが勝手にやり直される（途中で切れる / 中断扱いになる）」現象が断続的に発生しているため、**ECONNRESET（接続リセット）を検知したら自動でネットワーク診断を取り、証跡を残す**ための監視スクリプトを強化しました。

※チャット基盤側の「中断扱い」の内部理由自体はこちらから直接ログ参照できないため、まずは **発生時刻とネットワーク状態（DNS/443疎通など）を突合できる材料**を残す方針です。

### 変更点（警戒→実装→テストの成果）

#### `watch_cursor_econnreset.ps1` の堅牢化

ファイル: `scripts/watch_cursor_econnreset.ps1`

- **多重起動防止（ロックファイル）**
  - `logs/cursor_econnreset_watch.lock` を排他オープンし、既に実行中なら二重に走らない。
- **state JSON の破損耐性**
  - JSONが壊れていても落とさず、可能な範囲で復旧しつつログに `state_load_error` を残す。
- **offset 巻き戻り時の再検知を抑止**
  - 初回は EOF を基準にし、過去ログを「新規ECONNRESET」と誤検知しにくくした。
  - ログローテーション等でファイルサイズが小さくなった場合も安全側に補正。
- **Task Scheduler の変な引数に耐性**
  - `-MaxDirs` が配列/ネスト配列で渡っても壊れないよう正規化。
- **SYSTEM実行時のCursorログ探索**
  - `C:\\Users\\*\\AppData\\Roaming\\Cursor\\logs` を探索し、見つかった最新ログを監視対象にできる。
- **検知時に diag を自動実行（クールダウン付き）**
  - `-RunDiagOnHit` を付けた場合のみ `scripts/diag_cursor_net.ps1` を呼び出す。
  - `-DiagCooldownMinutes` で連続実行を抑制。

### 出力（証跡）

- 監視ログ（追記）: `logs/cursor_econnreset_watch_YYYYMMDD.log`
- ネットワーク診断ログ（追記）: `logs/cursor_netdiag_YYYYMMDD.log`
- 監視state（オフセット等）: `logs/cursor_econnreset_watch_state.json`
- 多重起動防止ロック: `logs/cursor_econnreset_watch.lock`

### 運用（手動実行）

PowerShell（`C:\\AI\\asagake` で）:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\watch_cursor_econnreset.ps1 -RunDiagOnHit
```

（必要なら）明示的にホスト名を指定:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\watch_cursor_econnreset.ps1 -RunDiagOnHit -DiagHostName api2.cursor.sh
```

### 期待する効果

- 「ECONNRESETが出た瞬間」に、DNS解決/443疎通などの結果がログに残るため、
  - 端末側（DNS/ネットワーク）要因なのか
  - 一時的な回線ブロック/到達不可なのか
を後から切り分けしやすくなります。
- state/lock の改善により、同じログを何度も拾って「同じ警報が繰り返し出る」事故を抑えます。

## 2) DailyReplay（18:00）メール多重送信の恒久対策（最小修正）

### 背景
- DailyReplay の結果メールが同日に複数回届くケースがあった。
- PowerShell 側（`scripts/run_daily_replay.ps1`）が「標準出力に `Mail sent` が含まれるか」で sent-flag を作成していたため、
  出力の揺れ・例外・リトライと噛み合うと、sent-flag が作られず再送が発生し得た。

### 変更点（根本）
1) **Python 側で sent-flag を作成**
   - `tools/simulate_daily_replay.py` がメール送信成功時に
     `logs/daily_replay_sent_YYYYMMDD.flag` を作成する（once-per-day を Python 自身が担保）。
2) **失敗を exit code で表現**
   - SMTP設定無し / recipient無し / 送信例外 は `exit code=2` で終了（成功は `0`）。
3) **PowerShell 側は出力パースをやめる**
   - `scripts/run_daily_replay.ps1` は「`Mail sent` を探して flag を作る」処理を削除し、
     Python の終了コードをそのまま返す（`exit $exitCode`）。

### 運用メモ
- 「同日に再送したい」場合は、sent-flag を削除するか、Python 直呼び出しで `--force-email` を使用する。
- 失敗時は Task Scheduler の「失敗時に再試行」が効く（送信成功するまでリトライ）。
  成功した瞬間に sent-flag が残るので、同日に再送はされない。
