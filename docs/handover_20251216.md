## 4) Top200「常連」銘柄の 1分足データ保存（永久保存）
目的:
- 週末バッチのネット取得を減らして高速化する（次回以降が速くなる）。
- Yahoo 側で古い 1分足が消えても、こちらで保存しておけば 90日・120日と伸ばせる。

方針（合意済み）:
- 「Top200 常連」を週次 TopVol から作り、**一度 Top200 に入った銘柄は、その後外れても永久に保存対象**にする。

### 選定基準（「Top200常連」＝どう選ぶか）
- 入力は `data/universe/topvol_YYYYMMDD.csv`（週次TopVol Top300）です。
- 直近の複数ファイル（デフォルトは **20ファイル**）を見て、
  - 何回出てきたか（appear_count）
  - 平均順位（avg_rank）
 で「よく出てくる＋上位に出やすい銘柄」を上に並べます。
- その上位 **200銘柄**を「Top200常連」として使います。
- さらに `--update-ever` を付けることで、
  **一度でもTop200常連に入った銘柄は、以後ずっと保存対象**（`top_regulars_ever.csv` に残り続ける）になります。

実装:
- 常連リスト更新: `tools/build_top_regulars_universe.py --update-ever`
  - 保存先: `data/universe/top_regulars_ever.csv`
- 1分足を毎日更新: `scripts/run_update_regulars_1m.ps1`（Windows のタスクで動かす）

注意:
- Yahoo の都合で「昔の日付を後から取り直す」のは成功しない日があります。
- ただし、**一度保存できた日付を再取得し直すことは基本的にありません**（既存ファイルがあればスキップします）。

## 7) ASAGAKE.xlsm（NewDashboardV2 / Orders）の確認メモ（2025-12-16）
※ここは「現状どうなっていたか」の事実メモです（修正はVBA更新で反映）。

- `NewDashboardV2` の `Name / PrevClose / VWAP` は RSS 関数の式が入っている（値が空でも式は存在）。
- `NewDashboardV2` の `J_th` が `#VALUE!` になりうる原因：
  - `NKY_ChgPct` / `TOPIX_ChgPct`（C2/F2）が「空文字（\"\"）」の時に、シートの式が割り算で `#VALUE!` になるパターンがある。
  - さらに、シート保護の影響で VBA が `J_th` を上書きできず、式が残ってしまう場合がある。
- `B3/D3` のトレンド表示が文字化けしている場合：
  - VBAの文字列が原因になりやすい（日本語の直書きが環境によって化ける）。
  - 対策として、トレンド表示は ASCII 表示（UP/DOWN/FLAT）に寄せる。
- `Orders` は `mode=preplace_demo` が記録されている（デモの先回り記録は動いている）。
  - `status=CANCELLED_AUTO` は、デモでは「自動で入れ替え」をしているために起こりうる（異常ではない）。

## 6) 時間帯を区切る／区切らない（暫定の比較）
「同じ候補・同じパラメータのまま、取引できる時間帯だけ変える」とどうなるかを先に確認しました。

- 実行: `analysis/compare_time_window_methods.py`
  - CUT: 候補CSVの `session` に従って時間帯を制限
  - NO_CUT: `session` を無視して終日（09:00-15:00）で許可
- 直近 20 平日相当（評価 19 日）の結果:
  - 合計損益: CUT 2,041,275円 / NO_CUT 2,048,987円（ほぼ同じ）
  - 日次差（CUT−NO_CUT）の95%範囲が 0 を跨いだため、この比較だけでは「どちらが明確に有利」とは言い切れません。

重要:
- これは「時間帯でパラメータを再学習する」比較ではなく、**同じパラメータのまま時間帯だけ変えた**簡易比較です。
- 本当に知りたい「時間帯ごとにパラメータを変える価値」があるかは、M0（全時間共通で再学習）と M3（時間帯別に再学習）を同じ条件で回す必要があります（時間がかかるので、次の段階で段取りします）。
