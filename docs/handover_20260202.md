# Handover 2026-02-02

## 背景（ユーザー報告）

- `ASAGAKE.xlsm` を `DEMO_RUNNING` で回している間、同じ Excel インスタンスで開いている他のブック作業が定期的に「ビジー/固まる」。

## 原因（推定・再現しやすいもの）

- `AutoTraderAdvanced.RefreshTrendsV2` が定期的に重い処理をまとめて実行していた。
  - `ws.Calculate`（シートの強制再計算）
  - `ApplyDynamicSignalsV2`（候補行の全走査・セル更新）
  - `PreplaceOrdersV2`（先回り注文の更新）
- さらに `ApplyDynamicSignalsV2` 内で `UpdateAllDriverTrends ws` を毎回呼んでおり、`RefreshTrendsV2` 側の `UpdateAllDriverTrends ws` と合わせて「ドライバートレンド更新」が二重で走り得た。

→ これらが、他ブック操作を含む Excel 全体の応答性を落とす主因。

## 対応（コミット）

- `excel/AutoTraderAdvanced.bas`
  - `ApplyDynamicSignalsV2` に `Optional skipDriverUpdate As Boolean = False` を追加。
  - `RefreshTrendsV2` からの呼び出しは `skipDriverUpdate:=True` にして、ドライバ更新の二重実行を回避。
  - DEMO 時の `ws.Calculate` を「原則スキップ」できるようにし、`demo_force_ws_calculate` で切替可能にした。
    - 例外: Excel 計算モードが手動の場合は、安全のため DEMO でも `ws.Calculate` を実行。

- `state/strategy_rules.ini`
  - `demo_force_ws_calculate=0` を追加（DEMOでの強制再計算をしないデフォルト）。

コミット: `1e167daf19`（"Reduce DEMO Excel busy impact (throttle calc/driver)"）

## 期待効果

- DEMO運用中でも、他のExcelブックの操作が「定期的に固まる」頻度/時間が減る。
- ドライバ更新の二重実行がなくなり、CPU負荷と再計算の連鎖が軽くなる。

## 運用メモ（ユーザー向け）

- `ASAGAKE.xlsm` 自体は Git で直接更新されない（バイナリのため）。
- 変更は `excel/AutoTraderAdvanced.bas` を更新し、`scripts/update_asagake_vba.ps1` で `ASAGAKE.xlsm` のVBAへ取り込む運用。

### 反映手順（手元PC）

1) `C:\AI\asagake` で `git pull`
2) Excelで `ASAGAKE.xlsm` を閉じる
3) PowerShell:
   - `powershell -ExecutionPolicy Bypass -File .\scripts\update_asagake_vba.ps1`
4) Excelで必要なら `Debug -> Compile VBAProject`（推奨）

### 設定（必要なら調整）

- DEMOでさらに軽くしたい:
  - `state/strategy_rules.ini` の `demo_calc_interval_sec` を長くする（例: 30→60）
  - `demo_driver_trend_interval_sec` を長くする（例: 60→120）
- DEMOでも強制再計算が必要になった場合:
  - `demo_force_ws_calculate=1`
