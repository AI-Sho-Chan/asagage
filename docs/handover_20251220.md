# 引継ぎ 2025-12-20（週末バッチの差分更新＋Top200永久保存）

## 1. 何を直したか（要点）
週末バッチが毎週「ほぼ同じ銘柄」に対して同じ計算を繰り返して重かったため、**品質を落とさずに“ムダな再計算だけ”減らす**仕組みを入れました。

### 1-1. 週末バッチの差分更新（品質は60日評価を維持）
週末バッチは「過去60営業日くらいでウォークフォワードテスト」をしますが、毎週増えるデータは基本5日分です。  
そこで、**前回の結果を使い回せる銘柄は使い回し**、必要な銘柄だけを再計算します。

やること（概念）:
- **新規に入ってきた銘柄**（先週までにいなかった） → その銘柄だけフルで再探索
- **最近成績が悪い銘柄** → その銘柄だけフルで再探索
- それ以外 → **前回週末の候補（candidates）を再利用**

※「結論を5日だけで決める」ではなく、**評価窓（60日）を維持しつつ、計算の手間だけ減らす**のが目的です。

### 1-2. 月1回のフル探索リセット
差分更新だけだと「古いデータのクセ」に引っ張られる懸念があるため、**月1回は全部をフル探索**して“リセット”します。
- ルール：**毎月第1金曜日はフル探索**

### 1-3. “異常時”はその銘柄だけフル探索
さらに、**直近10営業日で成績が悪い銘柄**は、その銘柄だけフル探索に回します（全銘柄リセットはしない）。

異常時判定（直近10営業日、最低5トレード以上の銘柄だけ判定）:
- 合計損益がマイナス、または
- PF < 1.0、または
- 勝率 < 0.5

この「要再探索リスト」を `abnormal_codes_latest.csv` として出します。

## 2. “Top200に一度入った銘柄は永久保存”の方針
ユーザー要望：**「一度Top200に入った銘柄は、その後Top200から落ちても、1分足データを保存し続ける」**

これにより、次の週末バッチで Yahoo から取り直す量が減り、**週末バッチの時間短縮に効きます**（特にデータ取得部分）。

### 2-1. どういうファイルで管理するか
- 永久保存リスト：`data/universe/top200_ever.csv`
- 直近コピー：`data/universe/top200_ever_latest.csv`
- 日付スナップショット：`data/universe/top200_ever_YYYYMMDD.csv`（任意）

### 2-2. どうやって増えていくか
- 毎週のTopVol（`data/universe/topvol_YYYYMMDD.csv`）から **上位200銘柄**を取り出す
- `top200_ever.csv` に **足していく（消さない）**

注意：
- Yahoo の制限で「すごく古い日を後から埋める（バックフィル）」は成功しない日があり得ます。
- ただし **毎日少しずつ追加で取れる分は増えていく**ので、長期的には蓄積が厚くなります。

## 3. 実装（どのファイルを触ったか）
### 3-1. 週末差分更新＋月1リセット＋異常時リセット
- `scripts/nightly_build_candidates.py`
  - `--weekend-incremental` / `--weekend-monthly-reset` / `--weekend-force-full-reset` を追加
  - “再計算が必要な銘柄だけ”を抽出して実行し、残りは前回候補を再利用
- `vm_run_weekend_only.sh`
  - 週末実行時に `abnormal_codes_latest.csv` をGCSから取得（あれば）
  - 週末実行時にTop200常連の1分足キャッシュをGCSから同期（あれば）

### 3-2. 異常時リスト（Windows側のDailyReplayから作ってVMへ渡す）
- `tools/build_abnormal_codes.py`
- `scripts/run_daily_replay.ps1`
  - DailyReplay完了後に異常時リストを生成し、GCSへアップロード（できるときだけ）
  - GCS：`gs://asagage-weekend-output/universe/abnormal_codes_latest.csv`

### 3-3. Top200永久保存リストの作成と、1分足の蓄積
- `tools/build_top200_ever_universe.py`
- `scripts/run_update_regulars_1m.ps1`
  - `top200_ever.csv` を更新
  - `top200_ever.csv` の銘柄の1分足を `tools/update_minute_cache.py` で取得して蓄積
  - `cache/yahoo_1m_regulars/` にミラーしてGCSへアップロード
  - GCS：`gs://asagage-weekend-output/yahoo_1m_regulars`

## 4. 運用メモ（用語の意味）
- バックフィル：**過去のデータを埋める**こと（取りこぼしを埋め直す）
- 差分更新：**前回から変わったところだけやる**こと（再計算を最小化）

## 5. 次に確認すること（運用チェック）
- VMが週末に必ず走るか（16:30 JST想定）
  - Cloud SchedulerのVM起動が16:20 JST、VM側のcronが16:30を想定
  - VMのタイムゾーンがUTCのままだとズレる可能性があるため、**cron時刻の見直し**が必要
- `abnormal_codes_latest.csv` のGCSアップロードが実際に成功しているか（Windows環境にgsutilがあるか）
