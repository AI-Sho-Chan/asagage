# 引継ぎ 2026-01-24（候補1件化の原因と恒久対策）

## 結論（何が起きていたか）
- **Excel の Import Candidates で「1銘柄しか入らない」**原因は、`output/excel/candidates_nextday.csv` が**ヘッダ1行のみ（実質0件）**に上書きされるタイミングがあったため。
- その状態で Import を実行すると、VBA 側は「読めた行数が 0〜1」になり、結果として **imported=1** のログが残ることがある。

## 根拠（ログ）
- `logs/morning_task_latest.log` にて `candidates_nextday: lines=1 records~=0` が出ていた。
- `logs/vba_events.log` にて `ImportCandidatesV2 done imported=1 path=...candidates_nextday.csv` が複数回出ていた（同日に imported=27 も出る＝CSV内容が変動していた）。

## 原因（どこで候補CSVが消されたか）
### 1) 週次スクリーニングが candidates_nextday を上書きしていた
- `scripts/run_weekly_screening.ps1` が、週次候補（`weekly_candidates_latest.csv`）を **`candidates_nextday.csv` にコピー**していた。
- 週次候補が **0行**の場合でも（ヘッダだけのCSV）、そのまま `candidates_nextday.csv` が**空に上書き**され得た。

### 2) 夜バッチ側が weekly を merge して候補が潰れる場合があった
- `scripts/nightly_build_candidates.py` の `aggregate_candidates()` が `weekly_candidates_latest.csv` を left-merge しており、weekly が空/極端に少ないと **候補が 0/1 に縮む**リスクがあった。

## 恒久対策（実装済み）
### `scripts/run_weekly_screening.ps1`
- 週次候補が **0行の場合は `weekly_candidates_latest.csv` を上書きしない**（skip overwrite）。
- 事故の元だった **`candidates_nextday.csv` へのコピーを削除**（週次は週次ファイルのみ）。
- 例外処理の `$_.Exception.Message` 参照ミスを修正。

### `scripts/nightly_build_candidates.py`
- `weekly_candidates_latest.csv` が空/少数の場合は **weekly merge をスキップ**（デフォルト閾値: 10 tickers）。
- フィルタ後 `df.empty` の場合に **`candidates_nextday.csv` を空で上書きしない**（呼び出し側のフォールバック集計に任せる）。
